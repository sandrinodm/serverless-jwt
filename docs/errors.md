Missing credentials have a bare Bearer challenge with the configured realm; they do not add an OAuth error parameter. Scope challenges contain the configured required scopes, never token input. The table uses the default realm `api` and an example required scope `read:orders`.

Every serialized error sends `Content-Type: application/json` and `Cache-Control: no-store`. A 503 sends `Retry-After` in seconds, rounded up and bounded to 1–30 (default 1). Server failures omit WWW-Authenticate.

Integrations await `onError(error, platformArgs)`. Return the platform response to override the default, or `undefined` for standard serialization. Consult the integration README for the exact platform arguments and response type. Before response commitment, a throwing, rejecting or unusable error-hook result selects the safe default and emits only a fixed integration diagnostic. Once a response is committed, the integration follows its documented platform error path rather than sending a second response. Do not return `error.cause` or log `auth.token`.

Invalid trusted configuration throws `ConfigurationError` at construction; it is distinct from a rejected request. Its reason is stable and its message never echoes an invalid option.
